# 用户鉴权 · VIP · API 配额方案（设计稿）

> 状态：**真登录已落地**（账号/邮箱 + 密码，httpOnly cookie 会话）；**VIP / 支付 / 读路径分叉仍为设计稿，未执行代码**
> 更新日期：2026-08-25
> 关联：[PROJECT_PLAN.md](../PROJECT_PLAN.md) §1.3 / 里程碑 M6+；产品边界见 `.cursor/rules/project-scope.mdc`
> 目的：官方 API 配额有成本；平台按付费套餐定时拉数落库；对用户按 VIP 限制**能看什么**，不按人分叉官方请求。

---

## 1. 目标与原则

### 1.1 要解决什么

- 平台向 API-Sports **付费订阅**（至少 Pro），定时任务按已订阅调度一直拉、一直写入本地库。
- 产品内对普通用户做限制：体验对齐今天「未订阅」那一档（公共盘口截止到 10:55 / 22:00、详情不补拉），VIP 读同一库里的最新盘口与完整分析。
- 官方配额用尽时，产品仍可读最近一次落库数据；不把 VIP 做成「每人打一套官方」。

### 1.2 原则

| 原则 | 说明 |
|------|------|
| 两层分开 | **平台层**：我们付钱给 API-Sports，调度与落库。**产品层**：用户付钱给我们，决定读路径。两层不是同一个开关。 |
| 单一公共池 | 全站一份 cron、一份库。不按用户跑两套定时任务，不为普通用户再打官方。 |
| 列表本地、补拉受限 | 页面、F5、下拉刷新、筛选只读本地。按需补详情只给「产品总闸开且 VIP 有效」的账号，并有独立预算；结果落库后其它 VIP 复用。 |
| 先身份、后 VIP、再支付 | 真登录 → 权益标记 → 支付写到期时间。管理员 `is_admin` **不是** VIP。 |
| Key 永不进前端 | 前端只调本项目 `/api/v1`。 |
| 非直播站 | 不做滚球轮询；普通用户与 VIP 都不提供「手动刷官方」入口（管理员详情「更新盘口」与运维页「批量更新盘口」除外，均属运维身份）。 |
| 不伪装即时盘 | 普通用户若展示盘口，必须是标明截止时刻的**公开档快照**，禁止把过期 `odds_json` 标成「即时盘」。 |

### 1.3 目标架构（未落地）

```
API-Sports（平台付费，至少 Pro）
        ↓ 定时任务按已订阅调度一直拉
  本地库（始终有最新：即时盘、初盘、中盘、临场、赛果、详情包）
        ↓ 公开档快照：每天 10:55 / 22:00 另写一份 odds_public_json
        ↓
  产品总闸（管理员开关） AND 该账号 VIP 未过期
        ↓                        ↓
     否：公开档读路径              是：VIP 读路径
     列表用公开快照               列表用即时盘 / 临场
     详情浅或不可进               完整分析包
     不触发官方补拉               共用定时任务的更新，不额外触发官方请求
```

**不要做成：** 库里只有一份 `odds_json`，查询时用 `captured_at < 10:55` 现场造旧盘（和升庄、手动更新、时区缠在一起，且会把过期水位伪装成当前盘）。

## 2. 角色与权益（产品分层）

额度数字为**示意**，管理员和运维身份可见。

### 2.1 两层开关（协同，不是同一个）

| 层 | 是什么 | 谁控制 | 含义 |
|----|--------|--------|------|
| 平台官方套餐 | 调度按 API-Sports 付费档跑 | 运维事实 / 配置 | **默认一直已订阅。** 现网管理员「订阅」开关历史上混了「没订官方」与「整站数据变密」，VIP 落地时应改语义为**产品总闸**（见下），不要再用 `ENABLE_FREE_QUOTA` 表示「我们没付钱给官方」。 |
| 产品总闸 | 管理员开关（可复用现网「订阅」控件，**改文案与语义**） | 管理员 | 关：全站按公开档读路径，即使某人有 VIP 记录也不开放完整能力（停售、维护、控展示）。开：允许对有效 VIP 开放完整能力。 |
| 用户 VIP | `user_entitlements`（`plan`、`expires_at`） | 支付 / 发卡 | 该账号是否买了完整分析。 |

**用户走 VIP 读路径** 当且仅当：`产品总闸开` **且** `该用户 VIP 未过期`。

游客、登录免费、VIP 过期、总闸关闭 → 全部走**公开档**。管理员调试可另设运维身份，不要和付费 VIP 混用 `is_admin`。

### 2.2 档位对照

| 档位 | 身份 | 列表盘口 | 详情 | 日推 / 质量星 | 官方补拉 |
|------|------|----------|------|----------------|----------|
| 游客 | 未登录 | 公开档快照（标明截至 10:55 / 22:00） | 不进全量分析 | 不展示依据，或仅「有推荐」不带盘口 | 禁止 |
| 登录免费 | 已注册、非 VIP | 同上 | 同上 | 同上 | 禁止 |
| VIP | 总闸开 + 未过期 | 即时盘；悬停可含初盘 / 临场（采集时间去重） | 完整：盘口、交锋、近况、阵容、伤病、简报、中盘/临场特征展示（若做） | 完整 | 仅热门未开赛缺包，计入 VIP/平台预算 |
| 管理员 | `is_admin` | 运维需要时可按 VIP 或单独豁免 | 可单场「更新盘口」，也可对当前比赛列表缺盘场次批量补齐 | — | 运维，不计入用户 VIP 商品 |

**不建议**把 VIP 做成「每人一套 ML 模型」。训练、自动推荐打分、官方同步继续服务端共享；VIP 买的是**读完整结果的权利**。日推与质量星按最新盘计算，默认视为 VIP 资产：公开档列表若完整展示「荐 + 即时盘 + 星级」，收费边界会漏。

公开档盘口必须带截止文案（例如「免费盘口截至 10:55」），避免被理解成当前市场。

## 3. 配额计量模型

### 3.1 计量动作（建议枚举）

| `action` | 含义 | 典型入口 | 池 |
|----------|------|----------|----|
| `scheduled_fixtures_sync` | 赛程 / 目录盘口 / 赛果（按**平台已订阅**调度，含晚间半小时轻刷） | 定时任务 | **公共**；与用户 VIP 无关 |
| `odds_public_snapshot` | 把当时即时盘冻进公开档（10:55 / 22:00） | 完整批次 / 22:00 轻刷成功后 | **公共、零额外官方请求** |
| `detail_package_enrich` | 单场展示包按需补拉 | VIP 打开详情且缺包 | **VIP/平台预算**；禁止游客与登录免费触发 |
| `admin_odds_refresh` | 管理员单场更新盘口 | 详情「更新盘口」 | **运维**；不计入用户商品 |
| `admin_prematch_odds_batch` | 管理员批量更新当前比赛筛选盘口 | 运维「批量更新盘口」 | **运维**；每个场次通常一次官方请求，不计入用户商品 |

公共池动作**不扣**用户额度，但应写入**平台配额日志**（监控日余量）。用户身份**不改变**固定批次频率。

现网「未订阅」的 08:05 / 10:55 / 22:00 是**公开档产品体验的参照**，不是 VIP 落地后的官方拉取节奏。平台订了 Pro 就按已订阅 cron 拉；普通用户只是读不到临场与完整详情。

### 3.2 账本（建议表）

`quota_ledger`（名可再定）每条至少含：

- `user_id`（可空 = 系统/公共）
- `action`、`scope`（如 `date` / `league_id` / `fixture_id`）
- `estimated_requests` / `actual_requests`（若可知）
- `status`：`accepted` / `denied` / `deduped`（命中 running 或已新鲜未打官方）
- `created_at`

用户侧日汇总：`user_quota_daily(user_id, day, used, limit, plan)`。

权益表（VIP 用）：`user_entitlements(user_id, plan, expires_at, source)`。`source` 可为发卡 / 支付渠道，首版可只支持管理员授予。

公开档快照：`pre_match_data.odds_public_json`（建议），与 `odds_json`（即时）、`odds_opening_json`（初盘）、`odds_mid_json` / `odds_late_json`（模型用中盘/临场）分开。列表公开档只读 `odds_public_json`。

### 3.3 扣费规则（建议）

1. 请求进入需打官方的路径前：先判产品总闸 + VIP；再 `can_spend(user, action, cost)`。
2. 若全局已有同类 sync `running` → 返回现有 `running`，记 `deduped`，**不扣**（推荐）。
3. 若本地已满足 TTL / 已有包 → 不打官方，不扣。
4. 真正发起官方 HTTP 前扣减（或预留 + 完成后结算），失败可回滚预留。
5. 额度用尽：HTTP `402` 或 `429` + 业务码 `quota_exhausted`；VIP 仍可读本地已有包。
6. 公开档用户打到补拉接口 → **403** + 业务码 `vip_required`，**零官方请求**。

## 4. 鉴权与会话

### 4.1 现状

- 前端：`LoginModal` 对接 `/auth/register`、`/auth/login`；不持有 token，只缓存用户名用于首屏渲染，`api/client.ts` 开 `withCredentials`。
- 账号：用户名或**邮箱**（含 `@` 时归一为小写后入库与比对，真源 `auth.normalize_account`）。
- 后端：`users` + `user_sessions`（30 天 opaque token）；token 只走 **httpOnly cookie**（`fa_session`）；收藏/方案按 `user_id` 隔离；游客桶 `user_id=""`。
- 运维：`users.is_admin`（非 VIP）；「我的 → 管理员设置」仅管理员可见；`/admin/*` 认会话 `is_admin`，兼容 `X-Admin-Key` 给脚本。授予：`python manage.py set-admin <账号>`；取消：`python manage.py unset-admin <账号>`。
- 首登认领：登录/注册时把游客桶**手动收藏**与**方案**迁到账号；`source=auto` 每日推荐留在游客桶，登录后列表合并可见。
- 官方 Key：只用管理员库内配置（见 [API_SPORTS_KEYS.md](./API_SPORTS_KEYS.md)）。

### 4.2 密码与传输（已定，勿再改方案）

| 约定 | 说明 |
|------|------|
| 落库 | 只存 `users.password_hash`：PBKDF2-SHA256、120000 轮、每用户随机盐，格式 `salt$hex`（真源 `auth.hash_password`） |
| 传输 | 请求体明文 + **TLS**；生产必须走 HTTPS（反代终止 TLS，建议加 HSTS），公网禁止 http |
| 前端预哈希 | **禁止**（含 MD5/SHA 等）。MD5 不可逆、无「后端解密」可言；把哈希值当密码比对等于换个名字的明文，抓包即可重放，还削平口令熵、焊死算法升级路径 |
| 会话载体 | **httpOnly + SameSite=Lax cookie**（`fa_session`）；生产置 `SESSION_COOKIE_SECURE=true`。不存 `localStorage`，页面脚本读不到 → XSS 偷不走会话 |
| CORS | `CORS_ALLOW_ORIGINS` 显式白名单 + `allow_credentials`；cookie 鉴权下**不得**用 `*` |
| 日志 / 响应 | 原始密码不进日志；token 不进任何响应体；`/auth/*` 只回 `id`、`username`、`claimed` |

DevTools 的 Network 面板挂在 TLS 之上，展示的是加密**之前**的请求体 —— HTTPS 站点在面板里同样是明文，这不是缺陷，勿据此改成前端加密。本地 dev 走 `http://localhost`（回环、不出本机）。

### 4.3 目标形态（VIP 尚未实现）

- 会话接口增加档位：`plan`（`anon` / `free` / `vip`）、`vip_expires_at`、`product_gate`（总闸是否开）。
- 读接口（列表摘要、详情包、日推）按 §2.1 裁剪；**卡在 API，不卡在按钮。**
- 不提供用户官方同步路由。
- 生产再定支付渠道；首版可管理员授予 VIP 便于联调。

密钥规范遵循现有 secrets 规则；OAuth 可选，非必须首版。

### 4.4 用户私有数据

收藏、计算器方案等**按用户隔离**；游客与登录共用本地库时靠 `user_id` 分桶。

| 约定 | 说明 |
|------|------|
| 游客桶 | `user_id=""`（空串，非 SQL NULL），仅承载共享的 `source=auto` 每日推荐；兼容 SQLite 复合主键 |
| 查询必带作用域 | `owner_is` / `normalize_owner_id`；登录用户收藏列表额外合并游客桶 `source=auto` |
| 鉴权依赖 | `CurrentUserId` 解析 `fa_session` cookie（可空）；写操作走 `RequiredUserId`，无效/缺失 → **401 请先登录** |
| 私有写操作 | `/favorites` POST/DELETE、`/bet-plans` 全部方法均要求登录；前端未登录先弹登录窗 |
| 登出清缓存 | 清账号侧客户端缓存：`fa-auth-user`、方案 session 缓存 / 遗留 localStorage、内存收藏与方案、计算器选单；**保留**主题、联赛勾选、记住账号、日期条、滚动位置 |
| 首登迁移 | 注册/登录时 `claim_anonymous_private_data`：认领历史游客桶里的手动收藏 + 方案；auto 不认领 |
| 收藏 PK | `(user_id, fixture_id)` |

已挂钩的表/接口：`favorite_fixtures.user_id`、`bet_plans.user_id`，以及 `/favorites`、`/bet-plans`、`/auth/*`。

**原则**：未登录时**不假装**做云同步或跨设备私有；私有写路径必须过 `RequiredUserId`；【关注】只返回当前账号的手动星标。自动推荐是否在公开档列表露出，按 §2.2 收口，避免未付费看到完整荐盘。

## 5. 与现有同步链路的对齐

现网管理员「订阅」仍控制**整站 cron 疏密**（未订阅 08:05 / 10:55 / 22:00；已订阅可开启全天每半小时密刷）。VIP 落地后的目标：

| 行为 | VIP 方案下 |
|------|------------|
| 平台拉取 | **始终按已订阅调度**（我们订 API-Sports）。用户 VIP 不改变批次频率。 |
| 产品总闸 | 管理员开关只决定是否对有效 VIP 开放完整读路径；关闭则全站公开档。 |
| 打开 / F5 / 筛选 | 只重读本地库 |
| 勾选非热门目录联赛 | 只改变本地默认筛选；目录联赛本身已在定时拉盘范围 |
| 列表盘口 | 公开档 → `odds_public_json`；VIP → `odds_json` / 临场 |
| 详情（VIP 落地前） | **暂不拦截**普通用户详情，避免现网提前残缺 |
| 详情（VIP 落地后） | 公开档不进全量分析、不触发补拉；VIP 可看完整包，缺包按预算补拉并落库 |
| 初盘 / 中盘 / 临场 | 继续按现网规则写入，供模型与 VIP；公开档列表不用临场顶替即时盘 |
| 单场「更新盘口」与比赛列表缺盘补齐 | 仍仅管理员 |

**固定边界**：列表不触发官方；公开档详情也不触发官方。VIP 权益落地前不提前改读路径。

## 6. 前端体验要点

- 「我的」：登录态、当前档位、VIP 到期、总闸关闭时的说明（「完整分析暂停开放」）。
- 公开档盘口标题带截止时间，不叫成与 VIP 相同的「即时盘」除非两者确为同一快照。
- 无权限进详情：可见原因（需登录 / 需 VIP），勿静默失败。
- 不展示官方刷新入口或用户官方配额；PC 与手机刷新都只重读本地。
- 游客与登录免费在盘口上可以相同；差异主要在云同步收藏/方案（已有）。

UI 细则后续写入 [frontend/FRONTEND_UI_SPEC.md](../frontend/FRONTEND_UI_SPEC.md)；本文件以业务与后端契约为主。

## 8. 风险与约束

| 风险 | 应对 |
|------|------|
| 固定批次超出官方日配额 | 监控每批消耗与官方日余量，按需缩小盘口预算；与 VIP 人数解耦 |
| 用户以为「VIP=实时比分」 | 文案写清：赛前分析，非直播；临场仍是开赛前最后一次刷新 |
| 公开档看到与 VIP 相同的即时盘 | API 裁剪 + 公开快照列；前端藏按钮不够 |
| 把过期盘口标成即时盘 | 公开档只用 `odds_public_json` 并标明截止时刻 |
| 调度失败导致数据偏旧 | 页面继续读最近版本；任务状态与日志明确失败批次 |
| 在线用户过多拖垮后端 | 只增加本地读压力，不放大官方请求 |
| 管理员开关被理解成退订官方 | 改文案为产品总闸；文档与设置页说明我们始终订 API-Sports |

## 9. 验收标准（本方案「完成」时）

- [ ] 列表 / F5 / 筛选入口均不触发官方 API
- [ ] 平台 cron 按已订阅调度，不因单个用户 VIP 增减官方请求
- [ ] 公开档列表盘口来自 10:55 / 22:00 快照并标明截止时间，响应中无临场即时盘
- [ ] 未满足「总闸 ∧ VIP」的账号无法用详情接口拉到完整分析包，补拉接口 403 且零官方请求
